How to use this page

Validated on RHOAI 3.5.2 · OCP 4.21 · NVIDIA L40S. Run everything from the repo folder after scripts/setup.sh.

  • Tick each item as you do it (saved in this browser). Both clocks stay paused at 00:00 until you click Start session; the same button pauses and resumes both. Each step's timer restarts from 0 when you open the step (amber at 80% of its slot, red when over); press t to restart it. Reloading the page pauses the clocks.
  • Every notebook has a "Reading the output" box under each result: what each line or column means, what good looks like, and what to do if it differs. Read them before presenting; use them to answer questions.
  • Keyboard: j next step · k previous · t restart step timer.
  • Every step has a Fallback box with the switch-over trigger. When it fires, open the video or report immediately; keep the session moving rather than troubleshooting live.
  • Videos are 1080p; waiting parts are fast-forwarded with an on-screen badge, and the stopwatch inside them shows real time.
Every terminal command assumes: 
cd ai-governance-demo        # the repo
oc login ...                 # as cluster admin
eval "$(scripts/env.sh)"     # URLs, model IDs, demo API keys

  • Use the key from any OpenAI-compatible client. In the terminal, paste the key between the quotes, then run the three calls: 
    K='paste-key-here'
curl -s $MAAS_URL/v1/models -H "Authorization: Bearer $K" | python3 -m json.tool | grep '"id"'
curl -s $MAAS_URL/v1/chat/completions -H "Authorization: Bearer $K" -H 'Content-Type: application/json' \
  -d '{"model":"'"$MODEL_ID"'","max_tokens":40,"chat_template_kwargs":{"enable_thinking":false},"messages":[{"role":"user","content":"Hello in five words"}]}'
curl -s -w '\nHTTP %{http_code}\n' $MAAS_URL/v1/chat/completions -H "Authorization: Bearer $K" -H 'Content-Type: application/json' \
  -d '{"model":"'"$SMALL_MODEL_ID"'","messages":[{"role":"user","content":"hi"}]}'
    Expect: (1) one model id, Qwen3-8B; (2) a short answer; (3) HTTP 403 "subscription aigov-chatbot does not include model…". Note the time of the first answer.
  • Bad credentials are rejected. Run: 
    curl -s -o /dev/null -w 'forged key: HTTP %{http_code}\n' $MAAS_URL/v1/models -H "Authorization: Bearer sk-oai-FORGEDKEY000000000000000"
curl -s -o /dev/null -w 'no key: HTTP %{http_code}\n' $MAAS_URL/v1/models
    Expect: forged key: HTTP 403 and no key: HTTP 401.
  • Revoke the key yourself. Back in the browser, API keys list → the ⋮ menu on the chatbot-live row → revoke/delete → confirm (check this menu exists in rehearsal). Then re-run the chat call from above → HTTP 403. If the menu isn't there, use this tested backup: 
    T=$(KUBECONFIG=.secrets/kube/aigov-app-chatbot oc whoami -t)
ID=$(curl -sk -X POST -H "Authorization: Bearer $T" -H 'Content-Type: application/json' $MAAS_URL/maas-api/v1/api-keys/search -d '{}' \
  | python3 -c 'import json,sys;print([k["id"] for k in json.load(sys.stdin)["data"] if k["name"]=="chatbot-live"][0])')
curl -sk -X DELETE -H "Authorization: Bearer $T" $MAAS_URL/maas-api/v1/api-keys/$ID -w 'revoked: HTTP %{http_code}\n'
  • An application without access. Switch to the aigov-app-unauth profile, Subscriptions tab: it shows "Request a subscription", so nothing has been granted. Click API keys → Create API key: the dialog says "No subscriptions available" and the Create button is disabled. Close the dialog.
